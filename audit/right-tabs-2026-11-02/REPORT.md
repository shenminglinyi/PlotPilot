# PlotPilot 工作台右侧面板 UX 审查

审查日期：2026-11-03  
页面：`/book/novel-1779619372689/workbench`  
范围：右侧“写作支撑 / 作品基础”全部主 Tab，以及知识库、角色档案、故事演进的主要子视图。  
证据：16 张真实页面截图；本报告是视觉与交互审查，不等同于完整 WCAG、性能剖析或跨浏览器测试。

## 结论

可以继续优化，而且不应再靠缩字号、压间距和局部补丁。根本矛盾是：右侧面板约 380px 宽，却同时承载了“快速参考”“复杂编辑器”“关系图”“时间轴”“版本图”四种完全不同的信息形态。

建议将右侧系统明确拆成两种容器：

1. **侧栏原生视图**：叙事简报、当前语境、伏笔账本、作品设定摘要、世界观摘要、道具摘要。只做快速读取、筛选和轻量操作。
2. **全宽工作区视图**：知识关系图、角色档案编辑、故事演进、时间轴、世界线、批量知识编辑。侧栏只显示摘要与“展开工作区”入口。

总体健康度：**需要结构性优化**。9 个主 Tab 中，伏笔账本最接近成熟；关系图、角色档案、故事演进时间轴、世界线在当前宽度下基本不可用。

## 最高优先级

### P1 — 侧栏与全页职责混淆

- 关系图在 380px 内显示 242 节点 / 1220 连接，结果是不可辨识的文字团。
- 角色档案采用“右侧栏内再套左侧角色导航 + 内容区”，有效内容宽度几乎归零。
- 故事演进时间轴再次拆成阶段、故事线、时间轴、详情四列，列宽不足以阅读。
- 世界线显示 51 个存档，却只看到空白网格与一条滚动条，核心信息没有进入可视区。

**建议**：这四类页面统一使用 `side summary -> workspace detail` 模式；侧栏保持单列，点击后把中央区域切换成全宽工作区，或打开可调整宽度的抽屉，不再嵌套列布局。

### P1 — 进度口径冲突

同一屏顶部显示“完成率 0.9%”，驾驶舱显示“全书进度 10.6%”，同时还有“53/56”和“53/500”。用户无法判断哪个是实际进度。

**建议**：建立单一进度领域模型，明确区分：`已规划章节完成率 53/56 = 94.6%`、`目标全书完成率 53/500 = 10.6%`、`字数目标完成率 22.2万/100万 = 22.2%`。不要再使用无口径的“完成率”。

### P1 — 数据规模与渲染策略不匹配

- 知识库“分章叙事”一次呈现大量章节编辑卡。
- 时间轴可访问树中一次挂载约 134 条事件。
- 世界线一次挂载 51 个快照。
- 手稿道具一次挂载 35 行。
- `SettingsPanel.vue` 对多数访问过的 Tab 使用 `display-directive="show"`，意味着访问后组件继续留在 DOM；长列表与监听器会持续占用内存。

**建议**：长列表统一虚拟滚动；只加载当前章附近窗口；图谱与时间轴进入全页后再初始化；隐藏 Tab 要么卸载，要么提供显式 `activate/deactivate` 生命周期暂停订阅、定时器和图形布局。

## 横向一致性问题

### 导航层级

现在同时存在：顶部分组、主 Tab、局部 Tab、卡片内切换、跳转按钮。它们视觉权重接近，用户难以判断自己处于哪一层。

建议最多保留三层：

1. 分组：写作支撑 / 作品基础。
2. 功能：主 Tab。
3. 视图：页面内部的 segmented control。

超过三层的内容应切到工作区，而不是继续嵌套。

### 页头与操作

多页把标题、说明、保存、AI、刷新放在同一横行，窄宽时正文被压成单字换行。统一页头应采用：第一行标题 + 状态；第二行短说明；第三行操作，或把次操作放入菜单。

### 文本密度

侧栏不应直接展示完整世界观、粗纲、状态锁和证据链。统一采用“结论一行 + 关键数字 + 展开详情”，正文在全宽页阅读。

### 可访问性

- 部分内部切换在可访问树中只是 `container/text`，不是 `tab/tablist`。
- 多个刷新、关闭、星标按钮只有图标，名称或帮助不稳定。
- 13px 图标和小型文本按钮点击目标偏小。
- 浅灰文字在浅色背景上对比不足。

建议补齐语义标签、键盘焦点、`aria-selected`，并将可点击区域统一到至少 32×32px（核心操作优先 40×40px）。

## 推荐实施顺序

1. **先重构容器模型**：定义 `SidePanelView` 与 `WorkspaceView`，把关系图、角色档案、故事演进迁出窄栏。
2. **统一进度口径**：修正 0.9% / 10.6% / 53/56 / 53/500 的语义冲突。
3. **建立长列表基础设施**：虚拟列表、分页窗口、按需加载、图表销毁/恢复协议。
4. **统一页头与导航组件**：减少每页独立 CSS 补丁。
5. **逐页精修**：优先时间轴、世界线、关系图、角色档案；最后再调整颜色、间距和微交互。
